# yandex-calendar-mcp

MCP-сервер, через который Claude читает и меняет Яндекс Календарь: смотрит
календари и события, создаёт, переносит и удаляет встречи, ищет свободные
окна. С календарём он говорит по CalDAV (`https://caldav.yandex.ru`), с
Claude — по MCP через stdio.

Сделан для личного использования: один аккаунт Яндекса, запуск на своей
машине. Многопользовательского режима, HTTP-транспорта и публикации в npm нет.

## Установка

Нужен Node.js (проект собирался и проверялся на Node.js 26). В папке
проекта выполните:

```bash
npm install && npm run build
```

Сборка кладёт сервер в `dist/mcp/server.js`. Именно этот файл запускает Claude.

## Пароль приложения

Сервер входит в Яндекс по паролю приложения, а не по паролю аккаунта.
**Обычный пароль от Яндекса не подойдёт** — сервер получит отказ 401.

Как завести пароль приложения:

1. Откройте Яндекс ID → **Безопасность** → **Пароли приложений**.
2. Создайте пароль с типом **«Календарь»**.
3. Этот пароль и пойдёт в `YANDEX_APP_PASSWORD`.

Если сервер ответил «Пароль приложения не принят», заведите новый пароль тем
же путём и замените значение `YANDEX_APP_PASSWORD`.

## Подключение

Сервер настраивается переменными окружения. Claude передаёт их из блока `env`
своей конфигурации.

| Переменная | Обязательна | Что это |
|---|---|---|
| `YANDEX_LOGIN` | да | полный адрес, например `name@yandex.ru` |
| `YANDEX_APP_PASSWORD` | да | пароль приложения из раздела выше |
| `YANDEX_DEFAULT_TZ` | да | часовой пояс IANA, например `Europe/Moscow` |
| `CALDAV_BASE_URL` | нет | по умолчанию `https://caldav.yandex.ru` |

Без любой из обязательных переменных сервер не запускается и пишет, какой
именно не хватает.

### Claude Desktop

Добавьте блок в `claude_desktop_config.json`. На macOS файл лежит в
`~/Library/Application Support/Claude/`, на Windows — в `%APPDATA%\Claude\`.

```json
{
  "mcpServers": {
    "yandex-calendar": {
      "command": "node",
      "args": ["/полный/путь/к/проекту/dist/mcp/server.js"],
      "env": {
        "YANDEX_LOGIN": "name@yandex.ru",
        "YANDEX_APP_PASSWORD": "пароль-приложения",
        "YANDEX_DEFAULT_TZ": "Europe/Moscow"
      }
    }
  }
}
```

> **Замените `/полный/путь/к/проекту` на настоящий абсолютный путь к папке
> проекта.** Узнать его можно командой `pwd` в корне проекта. Относительный
> путь не сработает: Claude запускает сервер не из папки проекта. Логин и
> пароль тоже замените своими.

После правки перезапустите Claude Desktop. Проверить подключение можно
просьбой вида «покажи мои календари» — Claude вызовет `list_calendars`.

### Claude Code

```bash
claude mcp add --scope user yandex-calendar \
  -e YANDEX_LOGIN=name@yandex.ru \
  -e YANDEX_APP_PASSWORD=пароль-приложения \
  -e YANDEX_DEFAULT_TZ=Europe/Moscow \
  -- node /полный/путь/к/проекту/dist/mcp/server.js
```

Путь `/полный/путь/к/проекту` здесь тоже нужно заменить. `--scope user`
делает сервер доступным во всех проектах, без него он подключится только в
текущей папке.

## Инструменты

Даты везде — ISO 8601 со смещением, например `2026-09-21T10:00:00+03:00`.
Календарь (`calendarId`, `calendarIds`) можно указать идентификатором или
названием; название сравнивается без учёта регистра. Если календарь не
указан, `create_event`, `update_event` и `delete_event` берут первый из
списка `list_calendars`, а `list_events` и `find_free_slots` смотрят все
календари. Событие везде определяется по `id` — это UID события.

| Инструмент | Что делает |
|---|---|
| `list_calendars` | Список календарей |
| `list_events` | События за период |
| `get_event` | Одно событие целиком |
| `create_event` | Создать событие |
| `create_events` | Создать несколько событий за один вызов |
| `update_event` | Изменить событие |
| `delete_event` | Удалить событие |
| `find_free_slots` | Найти свободные окна |

### `list_calendars`

Без параметров. Для каждого календаря возвращает `id`, `href`,
`displayName`, `color` и `readOnly` — можно ли в него писать.

### `list_events`

| Параметр | Обязателен | Описание |
|---|---|---|
| `from`, `to` | да | начало и конец окна |
| `calendarIds` | нет | в каких календарях искать, по умолчанию во всех |
| `query` | нет | подстрока в заголовке, описании или месте, без учёта регистра |
| `expandRecurring` | нет | раскрывать повторы, по умолчанию да |

Повторяющееся событие по умолчанию приходит отдельными экземплярами. У
каждого есть `instanceStart` — начало экземпляра, и `seriesId` — UID серии.
`instanceStart` нужен, чтобы изменить или удалить один экземпляр.

### `get_event`

| Параметр | Обязателен | Описание |
|---|---|---|
| `calendarId` | да | календарь события |
| `id` | да | UID события |

Возвращает событие целиком, с правилом повтора в исходном виде.

### `create_event`

| Параметр | Обязателен | Описание |
|---|---|---|
| `summary` | да | заголовок |
| `start`, `end` | да | начало и конец |
| `calendarId` | нет | календарь, по умолчанию первый |
| `description`, `location` | нет | описание и место |
| `timeZone` | нет | пояс IANA, по умолчанию `YANDEX_DEFAULT_TZ` |
| `allDay` | нет | событие на весь день |
| `recurrence` | нет | повтор, см. ниже |
| `reminders` | нет | напоминания: `[{ minutesBefore, method }]`, `method` — `display` или `email` |
| `attendees` | нет | участники: `[{ email, status }]`, см. «Ограничения» |

`minutesBefore` — за сколько минут до начала напомнить. Отрицательное число
означает «через столько минут после начала».

`status` участника — `needs-action` (по умолчанию), `accepted`, `declined`
или `tentative`.

`recurrence` устроен так:

- `frequency` — `daily`, `weekly`, `monthly` или `yearly`;
- `interval` — шаг повтора, по умолчанию 1;
- `byWeekday` — дни недели: `MO`, `TU`, `WE`, `TH`, `FR`, `SA`, `SU`. С
  порядковым номером — конкретное вхождение в месяце: `2MO` — второй
  понедельник, `-1FR` — последняя пятница;
- `until` — дата окончания, или `count` — число повторений.

Возвращает созданное событие с присвоенным `id`.

### `create_events`

Один параметр `events` — массив событий в том же формате, что у
`create_event`, не больше 50 за вызов. События создаются по одному. Ответ
содержит строку на каждое: создано или почему нет. Если часть событий не
создалась, уже созданные остаются — отката нет.

### `update_event`

| Параметр | Обязателен | Описание |
|---|---|---|
| `id` | да | UID события |
| `patch` | да | только те поля, которые меняются; поля те же, что у `create_event`, кроме `calendarId` |
| `calendarId` | нет | календарь, по умолчанию первый |
| `scope` | нет | что править у повторяющегося события, см. ниже |
| `instanceStart` | для `this` и `this_and_following` | начало экземпляра, от которого считается правка |

Поля, которых нет в `patch`, не меняются.

`scope` для повторяющегося события:

- `this` — только названный экземпляр (по умолчанию);
- `this_and_following` — этот экземпляр и все следующие;
- `all_series` — вся серия.

У одиночного события `scope` ни на что не влияет.

### `delete_event`

| Параметр | Обязателен | Описание |
|---|---|---|
| `id` | да | UID события |
| `calendarId` | нет | календарь, по умолчанию первый |
| `scope` | нет | `this`, `this_and_following` или `all_series`, по умолчанию `this` |
| `instanceStart` | для `this` и `this_and_following` | начало удаляемого экземпляра |

**Удаление необратимо.** У повторяющегося события по умолчанию исчезает только
названный экземпляр. Чтобы удалить всю серию, нужно явно передать
`scope: all_series`. Одиночное событие удаляется целиком при любом `scope`.

### `find_free_slots`

| Параметр | Обязателен | Описание |
|---|---|---|
| `from`, `to` | да | где искать |
| `durationMinutes` | да | минимальная длина окна в минутах |
| `workingHours` | нет | `{ start, end }` в формате `ЧЧ:ММ`, по умолчанию 10:00–19:00 |
| `weekdays` | нет | дни недели числами, 0 — воскресенье; по умолчанию с понедельника по пятницу |
| `calendarIds` | нет | какие календари учитывать, по умолчанию все |

Возвращает окна `{ start, end }` в UTC, например `2026-09-24T07:00:00.000Z`
— это 10:00 по Москве. Событие на весь день занимает весь рабочий день.

## Ограничения

Особенности CalDAV Яндекса, из которых следуют эти ограничения, проверены на
живом аккаунте 18 сентября 2026 года. Подробности и ответы сервера — в
[`docs/yandex-caldav-capabilities.md`](docs/yandex-caldav-capabilities.md).

- **Этот сервер не рассылает приглашения.** Сервер Яндекса объявляет планирование по
  RFC 6638, но этот MCP-сервер им не пользуется. Участники записываются в
  событие, но писем с приглашением наш сервер не отправляет, организатора не
  ставит и ответов участников не обрабатывает. По RFC 6638 без организатора
  и сам Яндекс рассылать приглашения не должен, но на живом аккаунте это не
  проверялось. Если человек должен узнать о встрече, пригласите его из
  веб-интерфейса Яндекс Календаря.
- **Свободно/занято чужих календарей недоступно.** `find_free_slots` ищет
  окна только по календарям вашего аккаунта. Когда свободны коллеги, он не
  знает.
- **Рабочие часы считаются в поясе `YANDEX_DEFAULT_TZ`**, а не в поясе
  компьютера, на котором запущен сервер.
- **Повторы раскрываются локально.** Серверное раскрытие повторов Яндекс
  игнорирует, поэтому экземпляры серий вычисляет сам сервер.
- **Часовые пояса берутся из встроенной базы IANA.** Описание пояса
  календаря Яндекс не отдаёт, поэтому `list_calendars` не показывает пояс
  календаря.
- **Календари задач не показываются.** Списки дел с задачами (VTODO) в
  аккаунте есть, но сервер их отфильтровывает: он работает только с
  событиями.

## Тесты

```bash
npx vitest run
```

Общий прогон работает без сети: разбор ответов сервера и iCalendar
проверяется на фикстурах, часть которых снята с настоящего аккаунта и
обезличена (см. `tests/fixtures/README.md`). `npm test` запускает тот же
набор в режиме наблюдения.

`tests/integration/roundtrip.test.ts` — полный цикл на живом аккаунте:
создать событие, прочитать, перенести, удалить. Он меняет настоящий
календарь, поэтому помечен `describe.skip` и в общий прогон не входит. Как
запустить его вручную, написано в комментарии в начале файла.
