# MCP-сервер для Яндекс Календаря — дизайн

Дата: 2026-09-18
Статус: утверждён к реализации

## 1. Цель

MCP-сервер, дающий Claude полный доступ к Яндекс Календарю через CalDAV.
Ближайшая прикладная задача — раскладывать полудни по проектам и
переставлять их, но набор инструментов делается полным, а не под один
сценарий.

## 2. Область

Входит:

- чтение календарей и событий, включая повторяющиеся;
- создание, обновление и удаление событий, в том числе пачкой;
- поиск свободных окон в собственных календарях;
- напоминания, участники, события на весь день.

Не входит:

- многопользовательский режим, HTTP-транспорт, публикация в npm;
- синхронизация на диск и работа офлайн;
- свободно/занято чужих людей и приглашения с ответами —
  протокол Яндекса этого не отдаёт (см. раздел 4).

## 3. Решения, принятые при обсуждении

| Вопрос | Решение |
|---|---|
| Объём | Полный набор возможностей, доступных протоколу |
| Стек | TypeScript + Node 26, официальный MCP SDK |
| CalDAV | Свой клиент на `fetch`, без готовой CalDAV-библиотеки |
| Формат iCalendar | `ical.js` — разбор и сборка VEVENT, RRULE своими руками не пишем |
| Аудитория | Личное использование, один аккаунт, транспорт stdio |
| Секреты | Логин и пароль приложения в блоке `env` конфига MCP |
| Правка повторов | Параметр `scope`, по умолчанию `this` |

Причина выбора своего клиента: контроль над поведением на стыке с
Яндексом и внятные ошибки вместо неопределённых значений из чужой
библиотеки.

## 4. Ограничения Яндекс CalDAV

Проверяются первым же шагом реализации, до написания инструментов:
один `PROPFIND` показывает заголовок `DAV:`, список календарей и
поддерживаемые REPORT-запросы.

Ожидания, требующие подтверждения:

- `calendar-query` и `calendar-multiget` — поддерживаются;
- серверное раскрытие повторов (`<C:expand>`) — под вопросом,
  поэтому раскрываем локально в любом случае;
- `sync-collection` (RFC 6578) — под вопросом, в первой версии не нужен;
- планирование по RFC 6638 (приглашения, ответы участников) —
  скорее всего отсутствует; поле `attendees` тогда пишется в событие,
  но письма участникам не уходят;
- запросы свободно/занято по чужим календарям — отсутствуют,
  `find_free_slots` работает только по своим календарям.

Если проверка покажет иное, набор инструментов расширяется, а этот
раздел обновляется.

## 5. Инструменты

### 5.1 Календари

**`list_calendars`** — без параметров.
Возвращает: `id`, `displayName`, `color`, `timeZone`, `readOnly`.

### 5.2 События

**`list_events`**

| Параметр | Тип | Примечание |
|---|---|---|
| `from`, `to` | ISO 8601 | обязательное окно времени |
| `calendarIds` | string[] | по умолчанию все |
| `query` | string | подстрока по заголовку, описанию и месту |
| `expandRecurring` | boolean | по умолчанию `true` |

Повторяющиеся события возвращаются раскрытыми в отдельные экземпляры,
каждый со своим `instanceStart` и ссылкой на серию.

**`get_event`** — `calendarId`, `id`. Возвращает событие целиком,
включая правило повтора в исходном виде.

**`create_event`** — поля доменной модели (раздел 6), кроме `id` и `etag`.
Возвращает созданное событие с присвоенным `id`.

**`create_events`** — массив таких же объектов. Выполняется по одному
`PUT` на событие, результат содержит по строке на каждое: успех или
причина отказа. Частичный успех не откатывается — это осознанный выбор,
откат потребовал бы транзакций, которых в CalDAV нет.

**`update_event`** — `calendarId`, `id`, изменяемые поля, `scope`.
Незаданные поля не трогаются.

**`delete_event`** — `calendarId`, `id`, `scope`.

`scope` принимает `this` (по умолчанию), `this_and_following`, `all_series`.
Умолчание выбрано так, чтобы неточная формулировка не стирала серию.

### 5.3 Планирование

**`find_free_slots`** — `from`, `to`, `durationMinutes`,
`workingHours` (например 10:00–19:00), `weekdays`, `calendarIds`.
Возвращает список свободных окон. Только по своим календарям.

## 6. Доменная модель события

```
Event {
  id            string          — UID из iCalendar
  calendarId    string
  summary       string
  description   string?
  location      string?
  start         string          — ISO 8601 со смещением
  end           string          — ISO 8601 со смещением
  timeZone      string          — IANA, например Europe/Moscow
  allDay        boolean
  recurrence    Recurrence?
  reminders     Reminder[]      — { minutesBefore, method }
  attendees     Attendee[]      — { email, status }
  etag          string          — для защиты от перезаписи
}
```

`Recurrence` описывается в читаемом виде (частота, интервал, дни недели,
конец серии либо число повторов) и переводится в RRULE внутри слоя `ical`.
Наружу RRULE не протекает.

## 7. Архитектура

```
src/
  config.ts          чтение и валидация env
  caldav/
    request.ts       fetch, Basic-авторизация, таймауты, повтор при 5xx
    xml.ts           сборка тел PROPFIND и REPORT, разбор multistatus
    discovery.ts     principal → calendar-home-set → коллекции
    objects.ts       calendar-query, multiget, PUT, DELETE
  ical/
    parse.ts         VEVENT → Event
    build.ts         Event → VEVENT
    expand.ts        локальное раскрытие повторов в окне времени
  domain/
    calendars.ts
    events.ts
    freeSlots.ts
  mcp/
    server.ts        регистрация инструментов, транспорт stdio
    tools/*.ts       схема параметров, вызов domain, формат ответа
```

Границы: `domain` не знает о существовании MCP, `mcp` не знает о CalDAV.
Слой `ical` не делает сетевых запросов и потому тестируется целиком на
фикстурах.

## 8. Протокол

Обнаружение, один раз за время жизни процесса, результат кешируется:

1. `PROPFIND /` Depth 0 → `current-user-principal`
2. `PROPFIND <principal>` Depth 0 → `calendar-home-set`
3. `PROPFIND <home>` Depth 1 → коллекции с `displayname`,
   `resourcetype`, `supported-calendar-component-set`, `calendar-color`

Чтение: `REPORT calendar-query` Depth 1, фильтр по компоненту VEVENT и
диапазону времени. Ответ содержит href, ETag и тело события.

Запись:

- создание — `PUT <home>/<calendar>/<uid>.ics` с `If-None-Match: *`;
- обновление — чтение свежего ETag, затем `PUT` с `If-Match`;
  ответ 412 означает, что событие изменили с другого устройства,
  и превращается в понятное сообщение, а не в тихую перезапись;
- удаление — `DELETE` с `If-Match`.

XML разбирается готовым парсером: пространства имён в CalDAV — не та
часть, ради контроля над которой выбран свой клиент.

## 9. Часовые пояса

На границе инструментов — ISO 8601 со смещением, плюс отдельное поле
`timeZone` в формате IANA.

Внутри события пишется `DTSTART;TZID=<зона>` с вложенным блоком
VTIMEZONE. Перевод в UTC не используется: правило «каждый понедельник
в 10:00» после перехода на зимнее время сместилось бы на час.

Определения VTIMEZONE берутся из готовой библиотеки с базой IANA.
Конкретный пакет выбирается на первом шаге реализации — по памяти
называть его здесь было бы ненадёжно.

Зона по умолчанию задаётся переменной окружения.

## 10. Повторы

Раскрытие всегда локальное, через `ical.js`. Серверное раскрытие не
используется, даже если Яндекс его поддерживает: локальное не зависит
от сервера и проверяется тестами без сети.

Семантика `scope` при правке и удалении:

- `this` — в серию добавляется исключение (`EXDATE`) и, для правки,
  отдельный экземпляр с `RECURRENCE-ID`;
- `this_and_following` — у исходной серии выставляется `UNTIL`,
  создаётся новая серия с изменёнными полями;
- `all_series` — правится сам исходный компонент.

## 11. Ошибки

Каждый класс получает текст, по которому понятно, что делать:

| Ситуация | Сообщение |
|---|---|
| 401 | пароль приложения не принят, и где его завести |
| 412 | событие изменили после чтения, нужно перечитать и повторить |
| 403, 507 | календарь только для чтения либо исчерпана квота |
| таймаут, 5xx | сеть или сервер недоступны, повтор выполнен N раз |

Пароль вырезается из логов, текстов ошибок и любых ответов инструментов.

## 12. Конфигурация

Переменные окружения, задаются в блоке `env` конфига MCP:

| Переменная | Назначение |
|---|---|
| `YANDEX_LOGIN` | полный адрес, например `name@yandex.ru` |
| `YANDEX_APP_PASSWORD` | пароль приложения типа «Календарь» |
| `YANDEX_DEFAULT_TZ` | зона по умолчанию, например `Europe/Moscow` |
| `CALDAV_BASE_URL` | по умолчанию `https://caldav.yandex.ru` |

Отсутствие обязательной переменной останавливает запуск с явным
сообщением, а не приводит к ошибке при первом вызове инструмента.

## 13. Тестирование

Разработка по TDD: тест пишется первым.

Без сети, на фикстурах:

- `ical/` — повторы, переход на летнее и зимнее время, события на весь
  день, кириллица и переносы строк в описании, экранирование запятых;
- `caldav/xml.ts` — разбор записанных ответов Яндекса, включая
  ответ с частичной ошибкой внутри multistatus;
- `domain/freeSlots.ts` — пересечения, смежные события, рабочие часы.

С сетью, запускается вручную и не входит в общий прогон:

- полный цикл на реальном аккаунте: создать, прочитать, обновить,
  удалить; в отдельном календаре, создаваемом под тест.

## 14. Риски

1. Ограничения Яндекса могут оказаться жёстче ожидаемых. Снимается
   проверкой из раздела 4 до написания инструментов.
2. Часовые пояса и переходы времени — источник ошибок, заметных не
   сразу. Снимается фикстурами на обе даты перехода.
3. Семантика `this_and_following` в CalDAV реализуется неочевидно и
   по-разному в клиентах. При расхождении с поведением веб-интерфейса
   Яндекса приоритет у веб-интерфейса.
